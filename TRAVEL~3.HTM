What's Going Wrong

Here's what Google flagged — in plain English.

🐢
Critical · Performance
26.2 seconds to load — the most extreme LCP I've seen

What's happening

Google's lab test measured a Largest Contentful Paint — the time before the main visible content appears — of 26.2 seconds on mobile. The First Contentful Paint (when anything at all appears) is 8.7 seconds. These are not rounding errors. They're a consequence of a 5,816 KB total page size, 967 KB of JavaScript that loads but never gets used, and what looks like Shopify's standard asset loading behaviour — a platform with significant performance overhead on mobile.

What this means for new clients

Someone in Sheffield searching "mobile vet Sheffield" who clicks your result and sees a blank screen for 8 seconds — then waits a further 18 seconds before the page fully loads — will almost certainly have left before then. They're not going to book. They'll find someone else. Given that your entire value proposition is about removing friction and stress from the vet experience, a website that's one of the slowest I've encountered is a significant problem.

The fix

Moving away from Shopify to a lightweight bespoke build removes the platform overhead entirely. No Shopify asset libraries, no unused JavaScript, no e-commerce framework loading on a vet information site. A bespoke build targets 97+ performance and under 2 seconds on mobile.

📐
Critical · Core Web Vitals
Core Web Vitals FAILED — CLS 0.11

What's happening

Cumulative Layout Shift (CLS) measures how much page content moves around while loading. A score of 0.11 means elements are visibly jumping or shifting as the page loads. Google's pass threshold is 0.10 — you're just over it. This causes your Core Web Vitals to fail overall, which is a direct search ranking signal.

What this means for you

CWV failure means Google classifieds your site as providing a poor user experience — and factors that into your position in local search results. Traditional veterinary surgeries in the same coverage area with passing CWV scores have a ranking advantage over you, even if your SEO content is better written.

The fix

Layout shift is caused by elements (typically images and fonts) loading without reserved space. A bespoke rebuild specifies dimensions for every element — nothing shifts after initial render. Target: CLS under 0.05, CWV passing across the board.

💻
Best Practices · Platform
Built on Shopify — a platform designed for e-commerce, not vet services

What's happening

Your site runs on Shopify — primarily an e-commerce platform. Shopify loads a significant amount of JavaScript and CSS related to shop functionality regardless of whether the page uses it. That 967 KB of unused JavaScript is largely platform overhead. Additionally, Shopify pages can trigger deprecated API warnings and third-party cookie issues (4 flagged) that pull down your Best Practices score to 54.

The fix

A bespoke HTML/CSS/JS build has no platform overhead — it loads only what the site actually needs. There's no shop, no product catalogue, no cart logic. Just a fast, clear veterinary services site.

📦
Performance · Page Weight
5.8 MB page — nearly 1 MB of JavaScript that never runs

What's happening

The total mobile page weight is 5,816 KB — nearly 6 megabytes. Of that, 967 KB is JavaScript that loads but never executes on the current page. This is Shopify loading its full toolkit regardless of what the page actually needs. Each of those megabytes adds to the load time, particularly on mobile data connections.

The fix

A bespoke build for a vet information site typically comes in under 1 MB. No unused JS, images compressed to modern formats, fonts loaded efficiently. The difference in perceived speed is dramatic.

♿
Accessibility
Buttons without accessible names

What's happening

Some buttons on your site don't have accessible names — meaning a screen reader can't describe what the button does to a visually impaired user. This pulls your accessibility score down from what could otherwise be near 100.

The fix

Every interactive element on a rebuilt site has an aria-label or visible text so screen readers can describe it accurately. Accessibility 97+ is the target.
